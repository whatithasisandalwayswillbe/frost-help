# Автоматическое резервное копирование

frost делает копии по расписанию с помощью встроенного планировщика вашей операционной системы. Между копиями в фоне ничего не работает.

## Как изменить расписание

`frost init` спрашивает, как часто делать копии. Чтобы изменить это позже:

```sh
frost config set schedule.every 6h
```

Можно выбрать `hourly`, `2h`, `3h`, `4h`, `6h`, `8h`, `12h`, `daily` и `weekly`. По умолчанию используется `daily`.

Чтобы выключить автоматическое копирование или снова включить его:

```sh
frost config set schedule.enabled false
frost config set schedule.enabled true
```

Любое из этих изменений сразу обновляет задание по расписанию.

## Когда выполняется копирование

| Планировщик | Ежедневно | Еженедельно | Чаще |
| --- | --- | --- | --- |
| launchd (macOS) и cron (Linux) | 03:17 | По воскресеньям в 03:17 | В 17 минут каждого часа |
| Планировщик заданий (Windows) | 03:17 | По воскресеньям в 03:17 | Раз в несколько часов, считая от момента создания задания |
| systemd (Linux) | В полночь | По понедельникам в полночь | В начале каждого часа |

Время указано по местным часам компьютера. systemd запускает каждое копирование со случайной задержкой до 5 минут.

## Пропущенные копии

launchd и systemd наверстывают пропущенное. Если в назначенное время компьютер был выключен или спал, копия запустится, когда он проснётся. cron и Планировщик заданий пропускают такие запуски, а следующий выполняется вовремя.

В Windows копирование по расписанию работает только пока вы вошли в систему. Оно не начинается при работе от батареи и прерывается, если отключить питание от электросети. В macOS и с systemd копирование по расписанию идёт с низким приоритетом, чтобы не замедлять компьютер.

## Задание по расписанию

| Система | Планировщик | Задание |
| --- | --- | --- |
| macOS | launchd | `~/Library/LaunchAgents/io.github.whatithasisandalwayswillbe.frost.plist` |
| Linux с systemd | Пользовательский таймер systemd | `~/.config/systemd/user/frost-backup.service` и `frost-backup.timer` |
| Linux без systemd | cron | Строка в crontab с пометкой `# frost-backup` |
| Windows | Планировщик заданий | Задача с именем `frost backup` |

Задание запускает `frost backup` с теми папками конфигурации и кэша, которые использовались при его создании. Если вы меняли эти папки, снова запустите `frost init`.

В macOS задание показано в разделе «Системные настройки > Основные > Объекты входа и расширения» (System Settings > General > Login Items & Extensions) под именем **Node.js Foundation**: так называется издатель среды выполнения, которая входит в frost. Если выключить его там, копирование по расписанию остановится, а `frost status` сообщит, что задание пропало. Чтобы остановить копирование по расписанию, лучше используйте `frost config set schedule.enabled false`.

С systemd frost пытается включить для вашего пользователя lingering (`loginctl enable-linger`), если может подтвердить, что lingering выключен. Благодаря ему копирование работает и после выхода из системы. Если включить lingering не удалось, после выхода копирование может остановиться. При удалении таймера frost выключает lingering, только если сохранил запись о том, что сам его включил.

## Журналы

| Планировщик | Где журнал |
| --- | --- |
| launchd, cron и Планировщик заданий | `frost.log` в папке кэша frost. См. раздел [Файлы и папки](#files-and-folders) |
| systemd | В журнале systemd. Читайте его командой `journalctl --user -u frost-backup` |

Журнал больше 1 МиБ очищается перед следующим запуском. Удалась ли последняя копия, показывает и `frost status`.

## Если задание пропало

Если задание удалили или выключили, `frost status` пишет "scheduled job is missing" (задание по расписанию отсутствует). Верните его командой:

```sh
frost config set schedule.enabled true
```
