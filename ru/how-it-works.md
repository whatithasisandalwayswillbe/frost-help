# Как работает frost

frost делает снимки ваших папок, разбивает файлы на зашифрованные блоки и отправляет только те блоки, которых ещё нет в хранилище.

## Коротко

1. **Обход.** frost проходит по папкам и пропускает всё, что есть в списке исключений. Файлы, у которых с прошлой копии не изменились ни размер, ни время изменения, повторно не читаются.
2. **Разбиение.** Изменённые файлы разбиваются на блоки примерно по 1 МиБ, причём места разреза определяет содержимое. Правка в середине большого файла затрагивает только соседние блоки.
3. **Шифрование.** Каждый новый блок сжимается, если от этого он становится меньше, а затем шифруется вашим ключом.
4. **Отправка.** В хранилище отправляются только блоки, которых там ещё нет.
5. **Сохранение снимка.** frost сохраняет список файлов и то, из каких блоков состоит каждый файл, как новый снимок.
6. **Проверка.** frost скачивает случайную выборку блоков и проверяет их.

## Снимки

Снимок фиксирует состояние ваших папок в момент копирования: каждый файл и каждую папку с содержимым, правами доступа и временем изменения. Каждый снимок полон сам по себе, поэтому любой из них можно восстановить без остальных.

Снимки используют общие блоки. Файл, который не менялся год, хранится один раз, сколько бы снимков его ни содержали. Поэтому много снимков почти не занимают лишнего места.

Если с прошлой копии ничего не изменилось, frost не сохраняет новый снимок. Он сообщает, что папки уже скопированы.

Идентификаторы снимков выглядят так: `maple-absurd-3f1c`, то есть два слова и ещё четыре символа. Как выбрать снимок по идентификатору или по времени, рассказано в разделе [Восстановление файлов](#restoring).

> frost пока не умеет удалять старые снимки, поэтому все они остаются в хранилище. Не удаляйте вручную объекты из папки frost в хранилище и не добавляйте правила, которые делают их просроченными. Снимки используют общие блоки, и удаление одного объекта может испортить сразу многие снимки.

## Ваш ключ

`frost init` создаёт на вашем компьютере случайный 256-битный ключ и показывает его в виде фразы восстановления из 24 слов. Ключ никогда не покидает компьютер. Всё, что отправляет frost, сначала шифруется этим ключом, включая имена файлов и структуру папок.

Прочитать копии может любой, у кого есть фраза и доступ к хранилищу. Без фразы не может никто. Подробнее в разделе [Фраза восстановления](#recovery-phrase).

## Репозиторий

frost хранит копии в одной папке хранилища, которая называется репозиторием. В ней лежат объекты четырёх видов:

| Объект | Что содержит |
| --- | --- |
| `frost.repo` | Идентификатор репозитория и версию его формата |
| `chunks/` | Данные и списки ваших файлов в зашифрованном виде |
| `snapshots/` | Небольшой зашифрованный заголовок для каждого снимка: когда, на каком компьютере и для каких папок он сделан |
| `trees/` | В каких блоках лежит список файлов каждого снимка |

Имена объектов выглядят как случайные идентификаторы, поэтому провайдер никогда не видит имён ваших файлов. Что именно видно провайдеру, описано в разделе [Безопасность и конфиденциальность](#security).

## Локальный кэш

frost ведёт в папке кэша на вашем компьютере учёт того, что уже отправлено, чтобы не перечислять всё хранилище при каждой копии. Раз в неделю этот учёт сверяется с хранилищем.

Кэш не жалко потерять. Если он пропадёт, следующая копия восстановит его по хранилищу и заново прочитает ваши файлы. Для восстановления файлов кэш не нужен совсем.

## Без фоновой службы

frost не работает в фоне. Автоматические копии делают обычные задания в планировщике операционной системы (launchd, systemd, cron или Планировщик заданий): они запускают frost, выполняют одну копию и завершаются. Подробнее в разделе [Автоматическое резервное копирование](#scheduling).

## Самопроверка

После каждой копии, которая сохраняет снимок, frost скачивает случайную выборку блоков и проверяет, что каждый расшифровывается и совпадает со своим идентификатором. Копия без изменений повторяет проверку, только если прошлой больше суток. Подробнее в разделе [Проверка резервных копий](#checking-backups).
