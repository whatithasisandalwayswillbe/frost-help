# ストレージの選び方

frost は、自分のサーバー、ドライブ、Permafrost、S3 互換サービスにバックアップを保存できます。どこに保存する場合も、すべてが先にコンピュータ上で暗号化されるので、ストレージを運用する人がファイルの中身を読むことはできません。

## 選択肢

| ストレージ | 向いている用途 | 必要なもの |
| --- | --- | --- |
| [セルフホスト](#self-hosted) | 自分で管理する NAS、自宅サーバー、VPS | SSH でのアクセス |
| [ローカルドライブ](#local-drive) | USB ドライブや 2 台目のディスク | バックアップの実行時に接続されているドライブ |
| [Permafrost](#permafrost) | frost のために作られたホスト型ストレージ | アクセスキー 1 つ |
| [クラウドプロバイダー](#cloud-providers) | Amazon S3、Cloudflare R2、Backblaze B2、Wasabi | バケットとそのキー |
| [その他の S3 互換ストレージ](#other-s3) | Ceph や SeaweedFS など自分で運用する S3 サーバー、またはほかの S3 サービス | バケットとそのキー |

セルフホストやローカルドライブなら、バックアップは自分で管理するハードウェアに置かれ、どこにもアカウントは要りません。Permafrost やクラウドプロバイダーは、管理するマシンを持たずに、家の外にバックアップを保管できます。

## 条件付き書き込み

frost には、ファイルを 1 回の操作で、しかもその名前が空いているときだけ作れるストレージが必要です。これにより、2 台のコンピュータがお互いのバックアップ記録を上書きし合うことを防ぎます。セットアップは接続時にこれをテストし、通らないストレージは使いません。ストレージ自体が対応していない場合、キーや設定を変えても解決しません。

| ストレージ | 条件付き書き込み |
| --- | --- |
| セルフホスト | OpenSSH サーバーで、ext4、Btrfs、XFS、ZFS、APFS、NTFS などハードリンクに対応したファイルシステムなら対応 |
| ローカルドライブ | NTFS、APFS、ext4、Btrfs、XFS で対応。ほかのファイルシステムはセットアップのテストに通る必要があります |
| Permafrost | 対応 |
| Amazon S3 | [ドキュメントに記載あり](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html) |
| Cloudflare R2 | [ドキュメントに記載あり](https://developers.cloudflare.com/r2/api/s3/api/) |
| Ceph | サーバーに実装済み。使っているバージョンがセットアップのテストに通る必要があります |
| SeaweedFS | [ドキュメントに記載あり](https://github.com/seaweedfs/seaweedfs/wiki/S3-Conditional-Operations)。使っているバージョンがセットアップのテストに通る必要があります |
| MinIO | サーバーに実装済みですが、メンテナンスは終了しています。使っているバージョンがセットアップのテストに通る必要があります |
| Backblaze B2 | 未確認。[アップロードのリファレンス](https://www.backblaze.com/apidocs/s3-put-object)に `If-None-Match` の記載がありません |
| Wasabi | 未確認。[API リファレンス](https://docs.wasabi.com/apidocs/operations-on-objects)からは対応を確認できません |
| Garage | 非対応 (メンテナーによる) |

S3 サービスの情報は、2026 年 10 月に各プロジェクトのドキュメントとソースコードで確認したもので、実際の動作テストは行っていません。最終的にはセットアップ自身のテストで判断します。

## 検討すること

- **家の外のコピー。** 自宅のドライブやサーバーは、コンピュータと同じ火事や盗難でなくなることがあります。別の場所にあるサーバー、Permafrost、クラウドプロバイダーならその心配はありません。かけがえのないものは、別の場所にも独立したコピーをもう 1 つ置いてください。
- **復元にかかる費用。** ダウンロードに料金がかかるクラウドプロバイダーもあります。全体を復元するとすべてをダウンロードしますし、抜き取りチェックのたびに少量のダウンロードも発生します。
- **アーカイブ用のストレージクラス。** frost はチャンクを直接読み戻すので、読む前に取り出し作業が必要なアーカイブ用クラスに、frost のオブジェクトを移さないでください。
- **削除と有効期限。** frost がバックアップを削除することはありません。スナップショット同士はチャンクを共有しているので、frost のフォルダ内のファイルを削除したり期限切れにしたりするライフサイクルルールやクリーンアップ処理は追加しないでください。
- **権限を絞ったアクセス。** frost には、専用のバケットにしかアクセスできないアクセスキーか、ほかの大切なものを変更できないサーバーのアカウントを渡してください。

## あとからストレージを変える

すべてをアップロードし直すことなく、バックアップを別の種類のストレージに移せます。詳しくは[バックアップの移動](#moving-backups)を参照してください。
