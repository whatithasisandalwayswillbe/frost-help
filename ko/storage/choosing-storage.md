# 스토리지 선택

frost는 직접 운영하는 서버, 드라이브, Permafrost, S3 호환 서비스에 백업을 저장할 수 있습니다. 어디에 저장하든 모든 내용이 먼저 컴퓨터에서 암호화되므로, 스토리지를 운영하는 쪽은 파일 내용을 읽을 수 없습니다.

## 선택지

| 스토리지 | 적합한 경우 | 필요한 것 |
| --- | --- | --- |
| [셀프 호스팅](#self-hosted) | 직접 관리하는 NAS, 홈 서버, VPS | SSH 접속 |
| [로컬 드라이브](#local-drive) | USB 드라이브나 두 번째 디스크 | 백업이 실행될 때 연결되어 있는 드라이브 |
| [Permafrost](#permafrost) | frost를 위해 만든 호스팅 스토리지 | 액세스 키 하나 |
| [클라우드 제공업체](#cloud-providers) | Amazon S3, Cloudflare R2, Backblaze B2, Wasabi | 버킷과 그 키 |
| [기타 S3 호환 스토리지](#other-s3) | Ceph나 SeaweedFS처럼 직접 운영하는 S3 서버, 또는 다른 S3 서비스 | 버킷과 그 키 |

셀프 호스팅이나 로컬 드라이브를 쓰면 백업은 직접 관리하는 하드웨어에 남고, 어디에도 계정이 필요 없습니다. Permafrost와 클라우드 제공업체는 관리할 장비 없이 집 밖에 백업을 보관해 줍니다.

## 조건부 쓰기

frost에는 이름이 비어 있을 때만 한 번에 파일을 만들 수 있는 스토리지가 필요합니다. 이렇게 해야 두 컴퓨터가 서로의 백업 기록을 덮어쓰지 않습니다. 설정 도우미는 연결할 때 이를 테스트하며, 통과하지 못한 스토리지는 받아들이지 않습니다. 스토리지가 지원하지 않는다면 키나 설정을 바꿔도 해결되지 않습니다.

| 스토리지 | 조건부 쓰기 |
| --- | --- |
| 셀프 호스팅 | OpenSSH 서버에서, ext4, Btrfs, XFS, ZFS, APFS, NTFS처럼 하드 링크를 지원하는 파일 시스템이면 지원 |
| 로컬 드라이브 | NTFS, APFS, ext4, Btrfs, XFS에서 지원. 다른 파일 시스템은 설정 도우미의 테스트를 통과해야 합니다 |
| Permafrost | 지원 |
| Amazon S3 | [문서에 명시](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html) |
| Cloudflare R2 | [문서에 명시](https://developers.cloudflare.com/r2/api/s3/api/) |
| Ceph | 서버에 구현되어 있음. 사용하는 버전이 설정 도우미의 테스트를 통과해야 합니다 |
| SeaweedFS | [문서에 명시](https://github.com/seaweedfs/seaweedfs/wiki/S3-Conditional-Operations). 사용하는 버전이 설정 도우미의 테스트를 통과해야 합니다 |
| MinIO | 서버에 구현되어 있지만 더 이상 관리되지 않음. 사용하는 버전이 설정 도우미의 테스트를 통과해야 합니다 |
| Backblaze B2 | 확인되지 않음. [업로드 참조 문서](https://www.backblaze.com/apidocs/s3-put-object)에 `If-None-Match`가 없습니다 |
| Wasabi | 확인되지 않음. [API 참조 문서](https://docs.wasabi.com/apidocs/operations-on-objects)로는 지원 여부를 확인할 수 없습니다 |
| Garage | 지원하지 않음(관리자 설명 기준) |

S3 서비스 정보는 2026년 10월에 각 프로젝트의 문서와 소스 코드를 기준으로 확인한 것이며, 실제 테스트는 하지 않았습니다. 최종 판단은 설정 도우미의 테스트가 내립니다.

## 고려할 점

- **집 밖의 사본.** 집에 있는 드라이브나 서버는 컴퓨터와 같은 화재나 도난으로 함께 사라질 수 있습니다. 다른 곳에 있는 서버, Permafrost, 클라우드 제공업체는 그렇지 않습니다. 대체할 수 없는 것은 다른 곳에 독립된 사본을 하나 더 두세요.
- **복원 비용.** 다운로드에 요금을 받는 클라우드 제공업체도 있습니다. 전체를 복원하면 모든 내용을 내려받고, 표본 검사를 할 때마다 소량을 내려받습니다.
- **보관용 스토리지 클래스.** frost는 청크를 바로 다시 읽으므로, 읽기 전에 복원 작업이 필요한 보관용 클래스로 frost의 객체를 옮기지 마세요.
- **삭제와 만료.** frost는 백업을 삭제하지 않습니다. 스냅샷끼리 청크를 공유하므로, frost 폴더의 파일을 삭제하거나 만료시키는 수명 주기 규칙이나 정리 작업을 추가하지 마세요.
- **제한된 접근.** frost에는 전용 버킷에만 접근할 수 있는 액세스 키나, 다른 중요한 것을 바꿀 수 없는 서버 계정을 주세요.

## 나중에 스토리지 바꾸기

모든 내용을 다시 업로드하지 않고도 백업을 다른 종류의 스토리지로 옮길 수 있습니다. 자세한 내용은 [백업 옮기기](#moving-backups)를 참고하세요.
