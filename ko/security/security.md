# 보안 및 개인정보 보호

frost는 무엇이든 업로드하기 전에, 사용자만 가진 키로 사용자의 컴퓨터에서 백업을 암호화합니다. 스토리지 제공업체도, Permafrost 운영자도, frost 개발자도 그 내용을 읽을 수 없습니다.

## 암호화되는 것

frost는 파일 내용, 파일 이름, 폴더 구조, 각 스냅샷의 세부 정보 등 백업 안의 모든 것을 암호화합니다. 키는 절대 컴퓨터 밖으로 나가지 않으며, 다른 어디에도 사본이 없습니다.

| 구성 요소 | 방식 |
| --- | --- |
| 키 | `frost init`이 컴퓨터에서 만드는 무작위 256비트 |
| 복구 문구 | 키 자체를 24개의 BIP39 단어로 적은 것 |
| 암호화 | XChaCha20-Poly1305. 객체마다 새 무작위 nonce를 씁니다 |
| 청크 이름 | 청크 내용에 대해 사용자의 키로 계산한 HMAC-SHA256 |
| 압축 | zstd. 암호화 전에, 크기가 줄어들 때만 압축합니다 |

## 제공업체가 볼 수 있는 것

S3 호스트든 Permafrost든 스토리지 제공업체는 다음을 볼 수 있습니다.

- 객체의 개수, 각 객체의 크기, 업로드된 시각.
- 어떤 객체가 청크, 스냅샷 헤더, 파일 목록 색인인지.
- 언제 백업하고 복원하는지, 그리고 어떤 IP 주소에서 하는지.
- 백업마다 업로드한 새 데이터 양. 이를 통해 얼마나 바뀌었는지 짐작할 수 있습니다. 새 내용이 없는 백업은 스냅샷을 저장하지 않으므로, 새 스냅샷이 생기면 무언가 바뀌었다는 것을 알 수 있습니다.
- 작은 파일의 압축 후 대략적인 크기. 하지만 그 파일이 무엇인지, 이름이 무엇인지는 알 수 없습니다. 큰 파일은 크기가 제각각인 청크로 나뉘므로, 원래 크기의 객체 하나로 나타나지 않습니다.

제공업체는 사용자가 특정한 알려진 파일을 가지고 있는지 확인할 수 없습니다. 청크 이름과 분할 위치 모두 사용자의 키에 따라 정해지기 때문입니다.

## frost가 막아 주는 것

- 제공업체나, 버킷의 사본을 손에 넣은 사람이 파일을 읽는 것.
- 사용자와 스토리지 사이의 네트워크에 있는 사람. 연결에는 TLS를 쓰며(로컬 서버용으로 암호화하지 않은 HTTP를 고른 경우 제외), 모든 객체는 따로 인증됩니다.
- 변조. 수정되거나, 바꿔치기되거나, 잘린 객체는 복호화에 실패하며, frost는 이를 조용히 받아들이지 않습니다.
- 복원이 사용자가 고른 폴더 밖에 파일을 쓰는 것.
- 변조된 frost 다운로드. 모든 릴리스에는 서명이 있으며, 설치 프로그램과 `frost update`는 설치 전에 서명을 확인합니다.

## frost가 막을 수 없는 것

- **사용자의 컴퓨터에 접근할 수 있는 사람.** 예약된 백업이 실행될 수 있도록 키 파일이 컴퓨터에 있습니다. 이 파일을 읽을 수 있거나 사용자 권한으로 프로그램을 실행할 수 있는 사람은 백업을 읽을 수 있습니다. 디스크 전체 암호화와 화면 잠금을 사용하세요.
- **스토리지의 데이터 손실.** 제공업체가 객체를 삭제하거나 내주지 않을 수 있습니다. 표본 검사로 알아챌 수는 있지만, frost가 막을 수는 없습니다. 잃어서는 안 되는 것은 독립된 사본을 하나 더 두세요.
- **숨겨진 스냅샷.** 제공업체가 최신 스냅샷을 숨기고 예전 것만 내줄 수 있습니다. 최신 스냅샷을 본 적이 있는 컴퓨터는 사라졌다고 보고하지만, 새 컴퓨터는 알아챌 방법이 없습니다. 그래도 내주는 스냅샷은 모두 진짜입니다.
- **시각과 크기.** 앞에서 설명했듯이 언제, 얼마나 백업하는지는 드러납니다.

## 컴퓨터에 있는 파일

macOS와 Linux에서 frost는 사용자 본인만 읽을 수 있도록 파일을 만듭니다. Windows에서는 사용자 프로필의 권한을 그대로 따릅니다.

| 파일 | 내용 |
| --- | --- |
| `key` | 복구 문구(평문) |
| `config.toml` | 설정과 스토리지 자격 증명 |
| `manifest-*.jsonl` | 청크 ID, 파일 경로, 크기, 수정 시각. 컴퓨터 밖으로 나가지 않습니다 |
| `frost.log` | 예약된 백업의 출력. 읽지 못한 경로도 포함됩니다 |

위치는 [파일 및 폴더](#files-and-folders)에 정리되어 있습니다.

## 권장 사항

- 복구 문구는 종이나 믿을 수 있는 비밀번호 관리자에 오프라인으로 보관하세요.
- 가끔 `frost key verify`를 실행해 적어 둔 복구 문구가 맞는지 확인하세요.
- frost에는 전용 버킷에만 접근할 수 있는 스토리지 자격 증명을 주세요.
- 가끔 `frost status`를 확인하고, 상태에 문제가 있으면 바로 살펴보세요.

## 보안 문제 신고하기

공개 issue는 열지 마세요. frost GitHub 저장소의 [Security 탭](https://github.com/whatithasisandalwayswillbe/frost/security)에서 **Report a vulnerability**로 비공개 신고해 주세요. 발견한 내용, 재현 방법, 공격자가 얻을 수 있는 것을 적어 주세요. 일주일 안에 답변을 드립니다.
